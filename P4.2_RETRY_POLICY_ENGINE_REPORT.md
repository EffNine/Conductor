# P4.2 Retry Policy Engine — Report

**Status:** COMPLETE
**Date:** 2026-08-22
**Scope:** `internal/resilience` (new), `internal/failure` (precision fix), `internal/handler` (wiring), `internal/config`, `pkg/retry` (removed)

---

## 1. Executive Summary

P4.2 introduces cause-aware same-provider retries driven entirely by the
canonical failure taxonomy from P4.1. A failed provider attempt is retried
only when its `failure.Class` is marked retryable; a server-advised wait
(`ProviderError.RetryAfter`, parsed from `Retry-After`) overrides computed
backoff when honored.

The engine is **zero-value-safe**: a handler constructed without
configuration keeps legacy behavior byte-for-byte (all pre-existing tests
pass unmodified). Production wiring flows from the revived `retry:` config
block, on by default with conservative limits.

The known P4.1 precision gap is also fixed: response-derived
`ProviderUnavailable` errors now classify by HTTP status instead of
collapsing into `network_error`.

## 3. Retry Policy Decisions

1. **Class-driven only.** The legacy status-code list is dead; verdicts come
   from `failure.PolicyFor(class).Retryable`.
2. **Retryable classes:** `rate_limited`, `timeout`, `capacity`,
   `upstream_error`, `network_error`. **Never retried:** `auth_failed`,
   `invalid_request`, `unknown` ("carefully" for network_error = bounded by
   low default MaxRetries and capped waits).
3. **Wait resolution precedence:** if honoring hints and
   `RetryAfter > 0` → exact hint capped at `max_retry_after_wait`
   (**no jitter** — deterministic compliance); otherwise exponential base
   `initial × mult^(n−1)` capped at `max_backoff`, jittered ±25%.
4. **Zero-value safety:** `resilience.RetryPolicy{}` is disabled; unit-test
   handlers without config are unaffected.
5. **Error truthfulness:** `Execute` returns the last provider error
   untouched (no wrapping) so downstream classification and client error
   mapping stay honest.
6. **Streaming boundary:** retries apply only to synchronous channel
   acquisition failures (pre-first-chunk); mid-stream behavior is untouched,
   per constraint.
7. **Telemetry:** execution telemetry attempt index now reflects real
   attempt counts (`len(attempts)-1`); identical to legacy values when
   retries never fire.
8. **Breakers untouched:** breaker accounting still sees one logical outcome
   per candidate; classification-aware counting remains P4.3.

## 4. Classification Fixes (P4.1 gap closure)

| Input | Before | After |
|---|---|---|
| Anthropic `overloaded_error` (status 529) | network_error | **capacity** |
| Upstream 503 via ProviderUnavailable type | network_error | **capacity** |
| Anthropic/Gemini 408 / 504 responses | network_error | **timeout** |
| Upstream 502/other 5xx responses (nil cause) | network_error | **upstream_error** |
| Transport failures (`client.Do`, Err≠nil) | timeout/network split | unchanged ✓ |

## 6. Constraints Honored

- No breaker changes (`Allow/Record*` semantics and call sites untouched)
- No router/scorer changes; fallback ordering unchanged (retries are
  same-provider, inside each candidate slot)
- `DecisionTrace` contract untouched
- Public `/v1/*` behavior unchanged: same success/error shapes; latency may
  include bounded same-provider retries when configured
- No analytics endpoints; no fallback executor (P4.4)
