# P4.4.2 Budget Enforcement — Report

**Status:** COMPLETE
**Date:** 2026-08-22
**Scope:** `internal/resilience` (budget model + executor gates), `internal/config`, `internal/handler` (wiring)

---

## 1. Executive Summary

P4.4.2 adds request-scoped execution budgets to `ExecutePlan`: a total
wall-clock deadline, a global attempt cap (retries included), and a token
amplification ceiling. Budgets are enforced inside the executor only — they
never influence router decisions, breaker classification of genuine provider
faults, or the public API.

Zero-value / `enabled=false` parity is preserved byte-for-byte with P4.4.1.

## 2. Semantics

| Dimension | Rule |
|---|---|
| **Deadline** | Timer cancels a derived context when fired; in-flight attempts abort and every remaining candidate is recorded as skipped (`deadline_exceeded`). **Streaming detach:** plans flagged `DetachAfterSuccess` disarm the timer on winner acquisition — the acquired stream's context stays alive so live streams are never cut off; idle-timeout continues to own them. Deadline cancellations are policy decisions and are **exempted from breaker accounting** (a budget abort never penalizes provider health). |
| **Attempt cap** | Total executions across all candidates, retries included. Pre-candidate gate skips with `attempt_budget_exhausted`; per-candidate retry policy shrinks so a candidate consumes at most the remaining cap (`MaxRetries = remaining-1`, never negative). Deterministic terminal result. |
| **Token guard** | Estimated once per request via `router.EstimateRequestTokens`. Blocks only ADDITIONAL attempts: fallbacks are skipped with `token_budget_exhausted` once `(attempts+1)*est > cap`, and retries shrink by remaining headroom. The primary request always runs at least once regardless of size. |

Skip reasons added: `deadline_exceeded`, `attempt_budget_exhausted`,
`token_budget_exhausted` (alongside P4.3's `circuit_breaker_open`).
