# P3.17 — API Authentication Report

Status: COMPLETE

Makes Conductor safe to expose as a remote, single-user, API-first runtime by
hardening and documenting the gateway API-key authentication layer. No CodeBro
integration was implemented or modified.

---

## 1. Executive Summary

Conductor already carried a minimal gateway-key auth layer (auth service +
global Bearer middleware with `/health` exempt). This phase hardened it into a
strict, deterministic contract and proved it with focused unit, middleware, and
HTTP integration tests:

- **Strict Bearer scheme**: `Authorization: Bearer <key>` is now the only
  accepted form. Bare keys, other schemes (`Basic`, `Key`), `Bearer` with no
  credential, or extra tokens are all rejected.
- **Timing-safe comparison**: both the configured key and the presented
  credential are SHA-256 digested before a constant-time compare, so the
  comparison no longer leaks key length.
- **RFC 7235 challenge**: every `401` now carries `WWW-Authenticate: Bearer`.
- **Distinct error codes**: missing → `missing_api_key`, invalid/malformed →
  `invalid_api_key`, both `401` with the established `authentication_error`
  envelope.
- **No leakage**: the API key / `Authorization` header is never logged, echoed,
  or stored; `GET /api/config` keeps reporting every key as `[REDACTED]`.

Existing OpenAI-compatible behavior, the P3.5 public mode contract, the P3.16
routing trace query contract, streaming behavior, and all existing tests are
preserved.

```
Client  ── Authorization: Bearer <key> ──►  middleware.Auth ──► Handler
                                                │  /health → Next() (open)
                                                │  parse + verify (constant-time)
                                                │  fail → 401 + WWW-Authenticate
                                                ▼
                                          (all other routes protected)
```

## 2. Audit of Existing Auth Architecture (Before This Phase)

| Component | Location | Finding |
|---|---|---|
| Auth service | `internal/auth/auth.go` | `Service.Authenticate` used `crypto/subtle.ConstantTimeCompare` on the raw strings — correct constant-time semantics, but length leaked (compare short-circuits on length mismatch). |
| Key generation | `internal/auth/generate.go` | `Generate()` = 32 random bytes hex-encoded (64 chars), `make gen-key` / `conductor gen-key`. |
| Middleware | `internal/middleware/middleware.go` | Global `app.Use(Auth(...))` in `middleware.Register`, registered after recovery/CORS/logging, before all route groups. Skipped only `GET /health`. Accepted a bare key or a `Bearer `-prefixed key; `Bearer` prefix stripped with a manual length check; no `WWW-Authenticate` header; single `invalid_api_key` code for both missing and invalid. |
| Config/secret handling | `internal/config/config.go` | `resolveAPIKey`: YAML `api_key` → `CONDUCTOR_API_KEY` env → persisted `data/conductor.api_key` (auto-generated, `0600`) if unset. `Config.Redacted()` maps the gateway key and every provider key to `[REDACTED]`; used by `GET /api/config`. |
| Error envelope | `apitypes.ErrorResponse` + `fiber.Map` | `{"error": {"message", "type", "code"}}`; auth used `type: "authentication_error"`. |
| Trace persistence | `internal/database/*` | `RequestLog` / `UsageRecord` store method/path/status/tokens — no headers, no keys (P3.14/15 contract). |
| Metrics | `internal/metrics/*` | Counters/histograms only — no header-derived labels. |
| Deployment probes | `fly.toml`, docker-compose | Liveness check hits `GET /health` (open). |

**Existing tests covering auth**: `handler_dashboard_test.go` and
`trace_query_test.go` each inlined a copy of the Bearer-strip middleware;
`trace_query_test.go` already asserted 401 for missing/wrong keys on the trace
API and scanned responses for key/secret leakage. There were **no** dedicated
tests for the `auth` or `middleware` packages.

## 3. Final API-Key Contract

```
Authorization: Bearer <CONDUCTOR_API_KEY>
```

| Case | HTTP | Envelope | WWW-Authenticate |
|---|---|---|---|
| Header absent / empty | 401 | `{"error":{"message":"Missing API key","type":"authentication_error","code":"missing_api_key"}}` | `Bearer` |
| Malformed (no `Bearer` scheme, bare key, `Bearer` w/o token, extra token) | 401 | `{"error":{"message":"Invalid API key","type":"authentication_error","code":"invalid_api_key"}}` | `Bearer` |
| Valid scheme, wrong key | 401 | `{"error":{"message":"Invalid API key","type":"authentication_error","code":"invalid_api_key"}}` | `Bearer` |
| Valid scheme, correct key | proceeds | — | — |
| Any `GET /health` | proceeds (open) | — | — |

The scheme is matched case-insensitively (`Bearer`/`bearer`/`BEARER`, per RFC
7235). Whitespace inside the token is not allowed (`Bearer a b` is rejected).

## 4. Protected vs Unprotected Endpoints

| Group | Endpoints | Protected |
|---|---|---|
| Inference (OpenAI-compatible) | `POST /v1/chat/completions`, `GET /v1/models`, `POST /v1/embeddings` | ✅ |
| Liveness | `GET /health` | ❌ (open — used by Fly.io / LB probes) |
| Dashboard/observability | `GET /api/models`, `/api/models/status`, `/api/models/reset-status`, `/api/models/force-probe`, `/api/auto/status`, `/api/health`, `/api/providers`, `/api/usage`, `/api/usage/costs`, `/api/logs`, `/api/config`, `/api/config/reload`, `/api/metrics`, `/api/circuit-breaker`, `/api/routing` | ✅ |
| Routing trace query (P3.16) | `GET /api/routing/traces`, `/api/routing/traces/:id` | ✅ |
| Tasks / agents | `POST/GET /api/tasks*` (create/list/get/tree/cancel/retry/resume) | ✅ |
| Cache/streams/runtime | `/api/cache`, `/api/streams`, `/api/runtime` | ✅ |

Scope rationale: the middleware is registered globally (`app.Use`), so every
route group registered afterwards — including the task API — inherits auth
automatically with no per-route opt-in. Only `/health` is exempt because
liveness probes must not require credentials. All read-only observability
endpoints remain authenticated because they expose topology, usage, metrics,
config, and traces.

## 5. Configuration

- **Env**: `CONDUCTOR_API_KEY` (preferred).
- **Config file**: `api_key: "${CONDUCTOR_API_KEY}"` in `config.yaml`.
- **Auto-generated**: if neither is set, Conductor generates a 64-hex-char key
  on first boot, persists it to `data/conductor.api_key` (`0600`), logs the
  path once (never the key), and warns the operator to set `CONDUCTOR_API_KEY`
  in production.
- **Rotation**: generate a new key with `make gen-key` / `conductor gen-key`,
  restart the gateway with the new value, and delete the old key file.

The key is never hardcoded. `GET /api/config` reports it as `[REDACTED]`.

## 6. Security Properties

- **Constant-time comparison**: `internal/auth/auth.go` hashes both the
  configured key and the presented credential with SHA-256 before
  `subtle.ConstantTimeCompare`. Digests are always 32 bytes, so neither the key
  length nor prefix equality is observable through timing.
- **Fail-closed**: an unconfigured service (`api_key` empty) rejects every
  request with `401` — the middleware never allows anonymous access even during
  misconfiguration.
- **No credential logging**: the request logger records method/path/status only;
  the auth middleware itself never logs the header or the key.
- **No credential exposure**: 401 bodies never echo the presented credential;
  `/api/config` redacts the gateway key and all provider keys; persisted traces
  and usage/log records contain no headers or keys (re-verified by existing
  `TestRoutingTraceNoSecrets` / `TestP314TraceNeverLeaksRequestContent` and the
  new `TestAuthIntegration_NoKeyLeakInAnyResponse` / `TestAuthIntegration_ConfigRedacted`).
- **CORS compatibility**: CORS middleware runs before auth, so preflight
  `OPTIONS` requests are answered without credentials while actual requests
  still require the Bearer key.

## 9. Limitations and Follow-Up

- **Single shared key, no per-scope keys**: one gateway key authenticates
  inference and dashboard endpoints alike. A future phase could introduce
  scoped keys (e.g. read-only `metrics`/`traces` key) without changing the
  middleware contract.
- **No rate limiting**: intentional — 401 handling is explicit and a reverse
  proxy / CDN should provide throttling in front of a public deployment
  (README already notes this).
- **No TLS in-process**: the key is sent in clear text if the gateway is
  fronted without HTTPS. Fly.io forces HTTPS (`force_https = true`); self-hosted
  deployments must terminate TLS at the proxy.
- **No key rotation API**: rotate by env/config + restart (documented above).
- **Task API shares the same key**: it was already protected globally; this
  phase only hardened the shared enforcement.

## 10. Final Verdict

**Conductor is ready for a CodeBro HTTP client to authenticate against it.** A
client can set `Authorization: Bearer <CONDUCTOR_API_KEY>` and call any
inference, dashboard, or trace endpoint over a single well-documented contract,
with deterministic `401` semantics, constant-time verification, and no
credential leakage across responses, traces, metrics, or logs. CodeBro
integration itself was intentionally not implemented in this phase.
