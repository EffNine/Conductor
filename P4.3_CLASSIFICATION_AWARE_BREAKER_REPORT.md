# P4.3 Classification-aware Circuit Breaker — Report

**Status:** COMPLETE
**Date:** 2026-08-22
**Scope:** `internal/breaker`, `internal/handler`, `internal/metrics` (additive stat)

---

## 1. Executive Summary

P4.3 makes circuit-breaker accounting consume the canonical failure taxonomy
and fixes two long-standing resilience defects: breaker credit granted on
stream *acquisition* instead of stream *completion*, and open primaries
aborting requests with an instant 503 even when eligible fallback candidates
existed.

## 2. Breaker Semantics (`internal/breaker`)

New API:

```go
func (b *Breaker) RecordOutcome(class failure.Class) // taxonomy-driven entry point
func (b *Breaker) RecordThrottled()                  // health-neutral throttle signal
```

Behavior by `failure.PolicyFor(class).BreakerImpact`:

| Impact | Classes | Effect |
|---|---|---|
| `count` | timeout, capacity, upstream_error, network_error, unknown | classic failure accounting; consecutive streak may open the breaker |
| `throttle_only` | rate_limited | increments a new `TotalThrottles` counter only; **never** touches the failure streak, never opens, never recovers, grants no half-open recovery credit |
| `none` | auth_failed, invalid_request | fully ignored |

Design notes:
- Throttling is deliberately health-neutral in both directions: it neither
  accumulates toward opening nor heals an existing failure streak.
- Legacy `RecordSuccess`/`RecordFailure` remain for direct callers;
  `RecordOutcome` is the single policy decision point.
- `/api/circuit-breaker` gained an additive `total_throttles` field.

## 3. Streaming Success Accounting Fix

Before: breaker `RecordSuccess()` fired when the channel was acquired — a
stream that died after two chunks counted as provider success.

After: acquisition no longer records anything. The `streamSession` carries
its breaker and `finalize()` (single once-guarded terminal point inside
`streamResponse`) records via `recordStreamBreakerOutcome`:

| Terminal state | Recording |
|---|---|
| `StreamCompleted` ([DONE] delivered) | success credit |
| error chunk w/ classified error | `RecordOutcome(class)` |
| channel closed without [DONE] | `network_error` → counts |
| idle timeout | `timeout` → counts |
| client disconnect / server shutdown | ignored (not provider-health signals) |

P4.2's pre-first-chunk retry behavior is preserved untouched; mid-stream
client-visible behavior is unchanged.

## 4. Open-primary Failover

Both dispatch paths (non-streaming, streaming) replaced their instant-503
primary gate with:

1. `primaryBlocked := resolved.Breaker.Allow() != allowed`
2. When blocked: skip primary execution (metrics + `request:primary_breaker_open`
   log) and fall through to fallbacks.
3. Fallback candidates now pass a per-candidate `Allow()` pre-check —
   open-breaker fallbacks are skipped instead of hammered.
4. Eligibility chain unchanged upstream: candidates are produced by
   `ResolveWithFallbackAndContext` / the decision pipeline under existing
   capability hard-filters, health scoring, and routing constraints; the new
   gate adds runtime breaker eligibility without loosening anything.
5. If nothing can serve (`primaryBlocked && err == nil`), the legacy
   contract is preserved exactly: HTTP 503 `circuit_breaker_open`.

Correctness guard: when blocked, `err == nil` means "never attempted" — both
success paths are gated on `err == nil && !primaryBlocked` to prevent
nil-response fall-through (caught by the new failover tests during
development).

All pre-existing handler/router/tracestore suites pass unmodified.
