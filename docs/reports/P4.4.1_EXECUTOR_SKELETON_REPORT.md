# P4.4.1 Executor Skeleton — Report

**Status:** COMPLETE
**Date:** 2026-08-22
**Scope:** `internal/resilience` (new executor), `internal/handler` (deduplication refactor)
**Nature:** Refactoring foundation slice — zero behaviour change intended and verified.

---

## 1. Executive Summary

P4.4.1 introduces the shared candidate-execution orchestrator
(`resilience.ExecutePlan`) and migrates both chat dispatch paths onto it,
removing ~150 lines of duplicated primary/fallback loop logic between the
streaming and non-streaming handlers (net **−138 lines** in handler.go).

No new runtime behaviour is added: budget enforcement, attempt persistence,
and retention pruning are explicitly out of scope for this slice.

## 2. Executor Design Choice

Evaluated: callback-result vs typed-operation interface vs generic structured
result. Chosen: **non-generic callback executor + structured Result**.

- The two dispatch shapes differ in result type (`*ChatCompletionResponse`
  vs `<-chan StreamChunk`). Generics would split the executor into two
  instantiations while post-winner handling still stays handler-side.
- Candidates expose `Op func(ctx) error`; results travel via the closure
  that built the candidate (`chatWinner`). The executor consumes only errors.
- This keeps `resilience` decoupled from apitypes/router/fiber entirely and
  gives budget/persistence (P4.4.x) a single seam to attach to later.

## 3. New API

```go
type Candidate struct {          // execution concerns only
    Index int                    // position in plan; 0 = primary
    ProviderName, ModelID, ProviderModelID string
    Breaker *breaker.Breaker     // nil → ungated/unchecked
    DeferSuccess bool            // streaming: credit lands at finalize
    Op      func(ctx) error      // one attempt; P4.2 engine wraps it
}
type Plan struct { Candidates []Candidate; Retry RetryPolicy; Sink Sink }
type Sink interface {
    CandidateSkipped(c, reason SkipReason)             // circuit_breaker_open
    CandidateFailed(c, err, attempts, duration)
    CandidateSucceeded(c, attempts, duration)
}
type Result struct {
    WinnerIndex int   // -1 none
    AttemptedAny bool
    FirstBlocked bool // primary skipped by breaker (legacy-503 driver)
    LastError    error
}
func ExecutePlan(ctx, Plan) Result
```

Traversal contract (identical to the pre-refactor loops): strict configured
order; open-breaker candidates skipped without execution; full P4.2 retry
budget per candidate via the unchanged `Execute` engine; failures classified
via `failure.Classify` → `RecordOutcome`; `DeferSuccess` candidates receive
no immediate success credit; first success stops traversal.

## 4. Code Moved From Handler

| Legacy inline block | New home |
|---|---|
| primaryBlocked gate + skip metrics/log | executor gate + `Sink.CandidateSkipped` |
| fallback `Allow()` pre-checks | executor gate |
| per-candidate retry `Execute` calls | executor inner loop (P4.2 engine reused verbatim) |
| classified `RecordOutcome` on failures | executor terminal accounting |
| immediate vs deferred success credit | `DeferSuccess` flag + existing finalize() path (unchanged) |
| request:provider_error / request:fallback_error / stream_* warn logs | `chatPlanSink.CandidateFailed` (identical names, fields, latency semantics: primary measured from request start, fallbacks from candidate start) |
| latency metrics, recordModelResult, recordExecutionTelemetry indices | `chatPlanSink.CandidateSucceeded/Failed` (legacy index formulas preserved: success `len(attempts)-1+index`, failure `index`) |
| legacy-503 tail | handler reads `Result.FirstBlocked && !AttemptedAny` |

Preserved verbatim in handler: cache lookup/store (primary-only caching),
usage tracking, completion logs, SSE headers/streamCtx lifecycle, session
construction, all-failed accounting (`IncrementStreamErrors` etc.).

## 5. Behaviour Preservation Evidence

- Full pre-existing suite passes unmodified: every P4.2/P4.3 test — including
  breaker-open failover e2e tests, streaming acquisition tests, legacy-503
  contracts, retry-through-handler tests — green through the new code paths.
- New unit coverage (10 tests): first/second/all-fail traversal, breaker-open
  primary skip, fall-to-healthy-second, strict ordering, retry-through-
  executor (flaky 429→success with correct throttle/success accounting),
  classification matrix, DeferSuccess no-immediate-credit, nil-sink/breaker
  safety.
- New e2e: two-fallback ordering preserved across both dispatch modes.
- Documented preserved semantic surfaced by testing: intermediate retry
  attempts never touch breakers — one logical outcome per candidate.
