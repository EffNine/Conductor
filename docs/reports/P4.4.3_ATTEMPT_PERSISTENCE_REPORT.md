**Status:** COMPLETE

## 1. Executive Summary

Every chat candidate attempt is now persisted asynchronously to SQLite:
handler sink notifications publish `AttemptRecord` events on the existing
bus; a bounded consumer writes `request_attempts` rows off the request path.
The isolation contract matches trace persistence exactly: saturation,
timeout, or failure of persistence NEVER affects request execution.

No hot-path database writes; no API changes; DecisionTrace untouched.

## 2. Architecture

```
chatPlanSink (Skipped/Failed/Succeeded)
  └─ emitAttempt → Handler.attemptEmitter          (nil when disabled)
       └─ main.go closure → eventBus.Publish(ExecutionAttemptCompleted)
            └─ AttemptPersistence.handle            (bounded: sem=16)
                 └─ AttemptStore.Save → request_attempts row
```

- **Schema** (`request_attempts`, additive AutoMigrate): id, created_atᵢ,
  request_idᵢ, correlation_idᵢ, virtual_model, mode, providerᵢ,
  provider_model_id, candidate_index, attempt_index, failure_classᵢ,
  outcome (`success|failed|skipped`), skip_reason, http_status,
  latency_ms, retry_wait_ms, retry_after_honored.
  ᵢ = indexed.
- **Skip reasons persisted:** circuit_breaker_open, deadline_exceeded,
  attempt_budget_exhausted, token_budget_exhausted.
- **HTTP status** extracted from `*provider.ProviderError.StatusCode` on
  failures (200 on success, 0 on skips).
- **Config:** `execution.attempts.enabled` (default true). Disabled leaves
  the emitter nil — zero allocations, zero events.
