# P4.4.4 Retention — Report

**Status:** COMPLETE
**Date:** 2026-08-23
**Scope:** `internal/database` (batched prune + retention runner), `internal/config`, `cmd/conductor/main.go`

---

## 1. Executive Summary

`request_attempts` storage is now bounded: rows older than the configured
retention window are removed in batched deletes — once at startup and then
periodically every hour while the gateway runs. Cleanup failures are logged,
never fatal; `retention <= 0` disables pruning entirely.

## 2. Semantics

| Aspect | Behaviour |
|---|---|
| Window | `execution.attempts.retention`, default **168h** |
| Startup sweep | Bounds any backlog before/at serving time |
| Periodic sweep | Every 1h until shutdown (context-cancelled via defer) |
| Batching | Per-statement cap of 1000 rows (`id IN (SELECT … LIMIT ?)` loop) so a large backlog cannot hold the SQLite writer long |
| Failure mode | Logged warning; next sweep retries. Storage growth without pruning remains possible only if SQLite itself fails repeatedly |
| Off-switch | `retention <= 0` → no pruning |
